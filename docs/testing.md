# 分层回归测试

测试数量不等于线上负担。这些测试由开发者单独运行，项目启动、扫描、开仓和平仓均不调用此入口。不为减少数量删除成交、未知订单、费用、资金及恢复回归，也不并发运行可能共享模块状态的现有后端套件。

## 常用命令

在项目根目录运行：

```bash
# 小改动的基础检查；这不是完整验收
./.venv/bin/python -B scripts/run_tests.py

# 页面脚本改动：全部前端套件
./.venv/bin/python -B scripts/run_tests.py --scope frontend

# 精确选择，可以混合后端和前端文件
./.venv/bin/python -B scripts/run_tests.py --tests tests/test_strategy_preview.py tests/test_strategy_channel_ui.js

# 先查看某组覆盖哪些文件，不加载和执行测试
./.venv/bin/python -B scripts/run_tests.py --scope strategy --list

# 重要改动完成后的一次完整验收
./.venv/bin/python -B scripts/run_tests.py --scope full
```

| 范围 | 用途 |
| --- | --- |
| `quick`（默认） | 数量分配、对冲安全、通道策略、行情基础、测试入口的代表性检查 |
| `frontend` | 自动收集所有 `tests/test_*.js`，适合纯前端修改 |
| `web` | 全部前端 + 面板接口、操作、策略预览、持仓展示 |
| `strategy` | 通道、目标回归、收益、资金费、网格、机会成本及历史统计 |
| `market` | 行情、原生推送、新鲜度、目录与发现节奏、Arcus 报价 |
| `history` | 执行账本、历史费用和成交证据、查询、回补说明 |
| `services` | 启停、停止标志、面板重载、浏览器启动 |
| `full` | 自动收集全部后端和前端回归；新测试自动纳入 |

## 选择规则

- 纯文案、样式：运行相关页面测试；纯脚本改动可用 `frontend`。
- 模块内改动：先运行相关文件或分组，修复失败后再复查受影响部分。
- 涉及实际成交、账户余额/持仓、费用与净盈亏、平仓、订单未知状态、进程恢复、公共配置或跨模块行为：开发中先局部检查，完成后做一次 `full`。
- 没把握影响范围时运行 `full`。局部分组是快捷入口，不是自动依赖分析，也不承诺覆盖模块的所有调用方。
- 完整回归通过后，只要没有新改动、新失败或未解决疑点，不重复跑同一套。

统一入口只接受 `tests/` 直接目录下的回归文件；根目录的旧 `test_*.py`、真实账户诊断或交易演练脚本不在发现范围内。`--list` 不导入测试模块。Node.js 缺失、测试加载失败、断言失败、前端进程超时或后端零用例均不能标记为通过。Node 可通过 `PATH` 或 `NODE` 指定。

每次运行在 `.run/test-results/last.json` 保存最近范围、文件清单、数量、通过状态、总耗时、模块导入耗时、最慢的十项后端用例以及每个前端套件耗时；报告会覆盖，避免累计文件。通过后也会明确显示本次范围，不能把快速检查当成完整回归。完整回归保留全量覆盖，日常速度提升来自减少不相关的重复验证。
