# 安装与配对

1. Chrome 打开 chrome://extensions，开启开发者模式，选择“加载已解压的扩展程序”，选此目录。
2. 本地行情面板的“网页报价桥接”中生成配对码。在扩展弹窗粘贴并连接。
3. 刷新正常登录的 Variational BTC/ETH 页面，手动填写想观察的基础数量，等待网页自身请求报价。不需要也不要为了测试而点击下单。
4. 面板应显示“网页参考报价”。若页面不请求报价、账户未启用、返回格式不符或超过 10 秒，自动回到公开缓存参考报价。当前账户条件下尚未验收真实报价响应，不能保证所有页面版本兼容。

扩展仅观察 /api/quotes/indicative，以及你手动操作后产生的订单/交易/仓位和 `/api/transfers` 响应；不发起交易、不改变订单表单、不读取 Cookie 或签名。结算采集只保留有限的资产、状态、金额、费用和资金费字段以及编号指纹，不保留原始响应、账号或认证字段。只有当该接口实际提供这些字段时才能显示；接口缺失或字段缺失时费用和净收益仍未知。手动观测事件只转发到本机面板，并在 `data/variational-manual-events.jsonl` 保存脱敏字段。配对码只有向当前本机进程发送参考行情和脱敏观测的能力，重启失效。它不是交易授权。

面板同时校验网页收到的时间和报价自身的服务端时间。若网页刚收到但报价服务端时间已经落后（例如约 48 秒），该报价会被拒绝并显示为缓存/过期，不会被用于新鲜价差判断。

新版在网页数量、币种和买卖价与该响应匹配时，可附带官网当前方向的 Est / Max 滑点（百分比换算 bps）；读取失败或语言不匹配时不填零、不猜值。更新扩展后在 Chrome 扩展页面重新加载，并刷新官网。

手动验证时，先启动面板并配对扩展，再在另一个终端运行：

```bash
.venv-execution/bin/python -B scripts/monitor_variational_manual.py --seconds 300
```

然后由账户所有者在已登录页面输入最小测试金额并自行点击一次提交按钮；监控器只打印脱敏请求/响应。最终必须在官网核对订单 `cleared`、交易 `confirmed` 和仓位变化，不能只看监控器输出。
